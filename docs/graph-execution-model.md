# 执行模型:事件驱动的图状态转换系统

> 本文档记录引擎执行语义的**最终决策**:世界是一个被信号与事件驱动、按
> 数据流因果序传播的程序(状态机)——**Event 是唯一传播事实,Event 改变
> 端口状态,节点从状态推导 Readiness,Activation 决定是否执行**。没有
> 全局轮次,没有时间序列,输出侧没有隐式信号。
> 本文档按 2026-08-19 端口语义抽象收敛模型重写(决策记录见
> [端口语义抽象收敛](./graph-port-capability-composition.md))。
> 相关文档:[图运行时总纲](./graph-runtime-overview.md) · [端口、绑定与输入资格](./graph-ports-bindings.md) ·
> [持久化与编辑](./graph-persistence-and-editing.md) · [节点协议(内核↔节点 ABI)](./node-protocol.md)

## 1. 核心命题

> **引擎是一个事件驱动的图状态转换系统:宿主注入输入事件,引擎从受影响
> 节点出发按数据流因果序传播(图路径遍历):事件改变端口状态、节点变
> Dirty、调度后检查 Readiness、Ready 即执行、产出即投递、投递即唤醒下游,
> 队列排空即静止,等待下一次输入。**

- 每个节点是一个状态机:读端口状态与自身状态,执行转移函数,写新状态、
  发输出;
- **执行顺序 = 注入序 + 数据流因果序**——数据齐全即触发、不受声明顺序
  延误;声明序只决定播种与并列分支的先后,不延误前向传播;
- 等待不是时间,是触发条件未满足:节点等待输入 = 状态机的 transition
  guard 不满足;
- 时间不是世界的基础维度:时钟、网络、用户、LLM 都是同一种东西——
  **改变某个端口状态的外部事件**,由宿主注入。

## 2. 节点与输入组

**节点 = 类实例;输入组 = 方法;输出组 = 方法的返回值。** 一个节点可以有
多个输入组,每个输入组一一对应一个输出组(声明,编辑器可见):

```
[输入组]              [输出组]
a, b, c        →      p, d
d, e           →      o
```

### 2.1 触发判定:Readiness 与 Activation

- **组触发 = 组 Readiness 检查**(`InputGroup.policy`,见 [端口、绑定与
  输入资格](./graph-ports-bindings.md) §2.4):

  | 策略 | Readiness 条件 | 适用 |
  |------|---------------|------|
  | `ON_ALL_DATA_READY`(默认) | 组内全部动态 Data 端口 pending | 组合节点(Join 类) |
  | `ON_ANY_DATA` | 任一动态 Data 端口 pending | 任一到达即处理 |
  | `ON_TRIGGER` | 任一 TriggerIn pending | 纯事件节点(Buffer.flush、LlmCall._result) |
  | `ON_DATA_AND_TRIGGER` | 数据齐 pending + Trigger pending | 显式门控执行(Timer.arm) |

- **资格条件叠加在 pending 之上**:已连接资格槽的端口,Readiness 为
  `pending AND level == HIGH`;未连接资格槽 = 条件恒成立;
- 执行后消费本轮 pending(重新等待);缓存值保持,新事件覆盖;
- **Dirty ≠ Execute**:任何相关输入状态变化(Data 或 Signal)都使节点
  Dirty、重新评估 Readiness——Data 与 Signal 在调度层面完全对称,都不
  拥有"触发权";真正决定是否执行的是 Readiness;
- **Activation 与 Readiness 分离**:基类携带默认触发策略(隐式激活——
  输入状态变化 → Dirty → 自动检查 Readiness);声明显式 TriggerIn 端口
  改变激活策略(显式激活——Buffer 的 flush);
- 触发端口(TriggerIn)= 函数调用入口(激活请求):Data Event 到达 = 载荷 +
  激活;Signal Event 到达 = 激活(每次 Signal Event 都是新的请求,同电平
  重复也有效);
- **组间隔离**:方法 A 的参数不参与方法 B 的计算——每组执行时只读本组
  输入;组间数据只能经**节点状态**(实例字段,全组共享)或**外部连线**传递;
- 节点状态与配置全组共享:类实例的字段,每个方法都能读,写受声明控制;
- 节点每轮运行中按**组声明序**检查各组,每组至多执行一次;前组产出经
  外部连线回连时可被同节点后序组当轮可见(顺序即语义);
- 旧"同步节点" = 只有一个组的节点;旧"函数节点" = 每个输入一个单例组的
  节点——组模型统一了二者,触发种类由策略显式表达;
- **源节点**(无输入组的节点)每轮运行执行一次(时钟、计时器、随机);
- 常量/全局读取绑定是**静态接口**:不参与触发、不消费,值随读随用;
- **初始化输入组**(可选,至多一个):像 `__init__`——实例创建时执行一次,
  可接受参数;初始化完成前,方法组不执行;读档(快照恢复)不重跑初始化;
- 节点种类(数据节点/信号节点/仅输入节点/仅输出节点)是节点基类的派生
  形态,由声明决定(见 [节点类型](./graph-node-types.md));
- 门控(enable)inactive:整节点不执行 → 无任何输出事件;数据照常接收缓存
  (节点暂停、数据不丢)。门控是**节点级资格**(level + pending),不是端口
  信号;端口资格关闭同样是"不参与执行",数据照常缓存——两级的语义
  一致,作用域不同。

### 2.2 组缓冲与覆盖

- 每个动态输入端口有**一格缓存**(Replace):新值覆盖旧值(重复值冲突是
  编辑责任);Append 缓存(声明)累积;
- 组执行后消费本轮 pending,重新等待新事件;
- 等待期间该组不执行;缓存中的值保持,资格恢复后照常参与。

## 3. 端口状态与资格:输入侧的控制面

**Event 是事实,State 是事实的当前结果,pending 是状态变化是否尚未被
当前执行消费的标记。** 信号 = 输入资格(qualification)。

### 3.1 端口运行时状态

| 端口 | 状态 | 行为 |
|------|------|------|
| Data(动态) | `value` + `pending` | pending = 有新事件未被消费;执行消费后 pending=false,value 保持 |
| Data(静态) | `value`(默认/绑定) | 恒可用,不参与触发、不消费 |
| Signal / 资格槽 | `level` + `pending` | level 保持;pending = 有新 Signal Event 未被消费;同电平重复 = 新资格 |
| TriggerIn | `pending` | 激活请求;执行消费 |

**资格(qualification)叠加规则**:

- 端口**未连接**资格槽:条件恒成立(结构属性,非隐式事件);
- 端口**已连接**资格槽:参与 Readiness 需 `pending AND level == HIGH`;
- 执行消费:Data.pending = false,Signal.pending = false;level/value 保持。

**低电平语义**(取代旧"inactive → 端口视为不存在、缓冲失效"):

| 状态 | 行为 |
|------|------|
| level = HIGH | 数据具备参与执行的资格;effective = cached |
| level = LOW | 数据照常接收、照常缓存(cached 保留);effective = **默认属性**;不参与 Readiness |

- LOW 不拒数据、不清缓存——禁用的是**参与资格**,不是接收能力;
- 端口恢复 HIGH 后:缓存值仍在,按 pending/Readiness 规则参与执行。

### 3.2 输出:Output Emission,无隐式信号

**数据节点**(不声明 SignalOut 的节点)的输出只有一个事实:

> 执行时产出 Data Event → 投递 → 唤醒下游。**没有隐式输出信号、没有
> 自动传导**。

- 节点执行时未写某输出 → 不投递;没有 Event = 没有事实发生;
- **不存在"对应输入组全关 → 输出信号关闭并传播"的规则**:被门控/熔断的
  节点不产出任何事件,下游不会收到任何通知——它们的等待属于正常暂停
  (上游有可恢复来源)或拓扑问题(结构性无法产生事件 → 诊断警告);
- **死等 = 拓扑诊断,不是内核机制**:静态可判定"上游无法产生事件、下游
  又在等待该输入"时给出警告,而不是让内核制造 LOW 信号维持错误拓扑;
- 需要控制流时显式构造:`Data → DataToSignal/比较器 → Signal → 受控输入`;
- 信号输出(仅**信号节点**声明):读输入信号、写输出信号,未写保持原电平;
  被门控时不执行,输出电平保持。信号节点可以接受数据(数据作为条件),
  让信号的逻辑在图中被显式表达;
- 数据节点永远不写信号——信号的产生与处理全部经由信号节点,编辑器里
  一目了然;
- 源节点(无输入组的节点)每 epoch 执行一次,正常时产出 Data Event;
- 子图边界:外部输入映射到内部端口(事件照常到达);内部输出映射到外部
  输出(事件照常产出);无信号传导层。

### 3.3 因果关系

- **事件可以异步传播,因果关系不能丢失**:同一次 NodeTurn 产出的多个
  Output Event 共享因果身份(causal_id),是 trace 因果时间线的结构化基础;
- "同因果组"是内核事实,"要求哪些成员形成一次输入"是端口语义——下游
  **不等全组**,避免把运行时变成隐式同步批处理。

## 4. 执行:脏节点传播(图路径遍历)

```
宿主注入输入事件(消息 / 外部完成 / 周期运行)
    → 注入目标按注入序入队,源节点按声明序播种(拉取型源节点尾播种)
    → 队列排空即静止:节点访问时满足 Readiness 即执行、产出即时投递、
      投递唤醒下游
    → 数据齐全即输出,不受声明顺序延误;无环部分结果与声明序无关
    → 每组每轮至多一次,反馈环跨轮迭代
```

**epoch 定义**:一次 `world.run(events)` 就是一个 epoch——一个逻辑因果
传播域:外部注入 → 播种 → worklist 传播 → 因果闭包 → 队列排空 → epoch
结束。反馈环在同一 epoch 内被执行预算阻挡,下一 epoch 重新迭代;外部事件
(宿主注入、异步结果)开启下一 epoch。

**三个职责分开**:

- **Mark = 为什么访问这个节点**——结构化因果事实(kind/目标端口/来源
  节点/来源端口/槽):事件到达、状态变化、播种……同一节点的多个 mark
  合并、出队时一并消费,原因不丢;
- **NodeTurn = 本轮该节点已消耗的执行机会**(evaluation budget):源
  step 一次、每组至多一次、纯信号源再触发至多一次、熔断冷却扣减一次
  ——run() 重建本表 = epoch 边界;
- **节点状态 = 跨轮保存什么**——状态字段、端口状态(value/level/pending)、
  熔断计数。

另有**因果 trace**(run + seq 确定性时间线):记录世界**为什么**变成这个
状态,独立于错误日志(程序打印了什么)、不进快照(世界是什么状态)。

- **因果序执行**:内部投递深度优先——一条传播路径走完再走兄弟分支(队列
  遍历,非调用栈递归);门控电平变化插队即时结算;已排队的数据触发不回头;
- **有界性来自 NodeTurn 预算**:队列排空即静止,不需要步数上限;
- **纯信号源**(Latch/AND/NOT/OR,无数据输入、无输入组)是电平函数:控制
  电平变化后同轮再触发一次——信号逻辑同轮收敛,不滞后;
- **全局写入按数据流因果序同轮可见**:拉取型源节点(无组、有数据输入的
  全局/常量读取者)尾播种——因果传播全部完成后执行,读到本轮最新写入;
- 环是合法设计(反馈环 = 跨运行迭代的状态机闭环):一个 epoch 内不递归
  展开,不挂起;
- 编辑器静态警告:无源环(没有源节点,永远不启动)、潜在死锁拓扑(上游
  结构性无法产生事件、下游在等待)。

## 5. 状态、确定性与异常

- 节点状态是**单写者**:执行时读取,产出新状态直接提交——无并发写、无
  事务冲突;
- 全局变量写 last-write-wins,顺序 = 数据流因果序(校验器对多写者告警);
- 随机性由**每节点独立随机流**提供(种子 = 世界种子 + 节点 id 派生):加
  节点、改声明序不扰动其他节点的随机轨迹;
- 节点异常:不产出任何输出 + 错误事件进日志;连续异常熔断、半开重试;
- **同一图、同一输入序列 → 同一结果**(因果序传播 + 独立随机流 = 确定
  可复现);
- **顺序无关性由 Readiness 保证**:Data Event 与 Signal Event 的到达顺序
  不进入可观察语义——执行条件只看端口状态的 pending + level,任一输入
  变化都重新评估(D1 S1 与 S1 D1 结果一致,见 [端口语义抽象收敛](./graph-port-capability-composition.md) §4);
- 单线程队列 + turn 内固定代码序的结构保证,不是时序巧合;不同节点之间
  的先后由注入序 + 数据流因果序决定,同输入序列结果唯一。

## 6. 时间、节奏与外部世界

- **内核没有时间**:没有仿真时钟、没有时间戳、没有事件队列的排序问题;
- 世界 = 状态机/程序:**注入 → 传播至静止**。运行频率由宿主决定:实时
  1 秒运行一次、消息到达才运行、编辑器预览连跑——节奏是宿主对"输入
  事件"的解释,不是内核机制;
- 外部系统(LLM 调用、HTTP)不属于内核:节点实现如何取得外部结果由宿主
  决定(同步阻塞,或挂起后注入完成事件),内核只认端口事件;
- 时钟/计时器等"时间节点"只是每轮运行执行一次的普通源节点——**时间
  只是世界可以接收的一类信号**。

## 7. 与旧模型(0.x / 1.0 前)的关系

| 旧语义 | 新语义 |
|--------|--------|
| 每拍全图扫描,所有就绪节点都执行 | 注入后按数据流因果序传播,只有 Readiness 满足的节点执行 |
| 每轮必发契约(未写输出补 None) | 不产出即不投递;没有事件 = 没有事实发生 |
| None 是"新包" | None 只是节点主动发的一个值 |
| 就绪 = 一次性 warm-up | 每组触发 = pending 齐备(消费清零,缓存保持) |
| 同步/函数两种触发种类 | 输入组模型统一:单组 = 同步,单例组 = 函数 |
| 门控照发 None、不传播 | 门控 = 节点级资格 LOW:不执行、不产出、数据照常缓存 |
| mask 是节点上的特殊控制输入 | 端口级资格槽(声明式,可选) |
| 每个数据端口自带信号(电平) | Signal 是可选声明(资格槽 / SignalIn);**输出无隐式信号** |
| 输出信号自动传导(全关 → 输出关闭) | **删除**:控制流用 Data→Signal 显式构造;死等 → 拓扑警告 |
| 信号 inactive → 缓冲失效 | level LOW → 数据照常缓存,effective = 默认属性 |
| 触发 = 数据到达(隐式)或 TriggerIn | Readiness 与 Activation 分离:状态变化 → Dirty → Readiness;TriggerIn 显式覆盖激活策略 |
| 数据包时间戳 / 轮次计数 | 无(事件即当下;日志用事件序号对齐) |
| 节点执行顺序无关 | 数据流因果序(传播即执行),确定性可复现 |

被否定的中间方案:

- ❌ **时间坐标 (t, δ, sequence) + 事件日历**:为"不同事件触发时间"建立
  的完整时间系统,复杂度不成比例。事件队列是实现的内部细节,不是世界
  模型;
- ❌ **拍事件作为内核机制**:节奏是宿主对输入的解释,内核不定义"拍";
- ❌ **全图重复扫描至静止**(曾作过渡实现:多遍扫描,收敛由触发驱动):
  脏节点传播只访问受影响的节点,队列排空即静止;
- ❌ **输出信号自动传导 / "无输出 → LOW 事件"**:"没有发生事件"被编码成
  事件 = 无事件事件;把拓扑设计问题(死等)转嫁为运行时语义;控制逻辑
  应显式存在于图中(Data → Signal);
- ❌ **下游等全因果组**:把事件传播变回隐式同步批处理;"同因果组"是内核
  事实,"等齐"是端口语义,二者分离。

## 8. 被否定的方案(沿用)

- ❌ **令牌队列 join**(每个输入消费一个令牌、以最慢输入为节奏):引入队列
  堆积、丢弃策略、背压三个新问题;一格覆盖缓存已经给出最简语义;
- ❌ **零延迟级联传播**(函数调用):反馈环导致无限递归;脏节点传播(队列
  遍历,非调用栈递归)+ 每组每轮至多一次解决;
- ❌ **共享黑板**:数据写入的消费时机不确定;数据随事件流动则路由与消费
  时机由连线结构确定;
- ❌ **运行时类型强制**:类型注解只做编辑期静态检查,运行时鸭子类型
  (见 [节点类型](./graph-node-types.md) §6)。
