# 执行模型:事件驱动的图状态转换系统

> 本文档记录引擎执行语义的**最终决策**:世界是一个被信号与事件驱动、按数据流因果序传播的程序(状态机)——节点因事件执行,端口信号决定网络的通断。没有全局轮次,没有时间序列。
> 相关文档:[图运行时总纲](./graph-runtime-overview.md) · [端口、绑定与控制信号](./graph-ports-bindings.md) · [持久化与编辑](./graph-persistence-and-editing.md) · [节点协议(内核↔节点 ABI)](./node-protocol.md)

## 1. 核心命题

> **引擎是一个事件驱动的图状态转换系统:宿主注入输入事件,引擎从受影响节点出发按数据流因果序传播(图路径遍历):节点触发即投递、投递即唤醒下游,队列排空即静止,等待下一次输入。**

- 每个节点是一个状态机:读输入与自身状态,执行转移函数,写新状态、发输出;
- **执行顺序 = 注入序 + 数据流因果序**——数据齐全即触发、不受声明顺序延误;声明序只决定播种与并列分支的先后,不延误前向传播;
- 等待不是时间,是触发条件未满足:节点等待输入 = 状态机的 transition guard 不满足;
- 时间不是世界的基础维度:时钟、网络、用户、LLM 都是同一种东西——**改变某个端口状态的外部事件**,由宿主注入。

## 2. 节点与输入组

**节点 = 类实例;输入组 = 方法;输出组 = 方法的返回值。** 一个节点可以有多个输入组,每个输入组一一对应一个输出组(声明,编辑器可见):

```
[输入组]              [输出组]
a, b, c        →      p, d
d, e           →      o
```

- **组触发 = 组触发策略判定**(`InputGroup.policy`,见 [端口、绑定与控制信号](./graph-ports-bindings.md) §2):
  - `ON_ALL_DATA_READY`(默认):组内全部有效(未关闭)连线数据输入都收到新值 → 执行;
  - `ON_ANY_DATA`:任一有效连线数据输入有新值 → 执行;
  - `ON_TRIGGER`:任一 TriggerIn 收到激活请求(数据线到达或信号线电平变化)→ 执行;
  - `ON_DATA_AND_TRIGGER`:数据齐 + 激活请求 → 执行;
  - 触发后该组输入缓冲清零(瞬态)、触发事件消费,重新等待;
- **触发端口(TriggerIn)** = 函数调用入口(激活请求),与数据参数(输入组 `inputs`)分离:数据决定"用什么",触发决定"何时调用";数据线到达 = 载荷 + 激活,信号线电平变化 = 激活(双沿,电平保持不重复);
- **组间隔离**:方法 A 的参数不参与方法 B 的计算——每组执行时只读本组输入;组间数据只能经**节点状态**(实例字段,全组共享)或**外部连线**传递;
- 节点状态与配置全组共享:类实例的字段,每个方法都能读,写受声明控制;
- 节点每轮运行中按**组声明序**检查各组,每组至多执行一次;前组产出经外部连线回连时可被同节点后序组当轮可见(顺序即语义);
- 旧"同步节点" = 只有一个组的节点;旧"函数节点" = 每个输入一个单例组的节点——组模型统一了二者,触发种类由策略显式表达,不再依赖端口标记;
- **源节点**(无输入组的节点)每轮运行执行一次(时钟、计时器、随机);
- 常量/全局读取绑定不参与触发(绑定与连线正交:连线到达覆盖默认值,缓冲为空时读默认值);持久输入用绑定、瞬态输入用连线,不需要端口新机制;
- **初始化输入组**(可选,至多一个):像 `__init__`——实例创建时执行一次,可接受参数;参数用绑定(常量/资产引用)或连线(就绪后执行一次);**初始化完成前,方法组不执行**;读档(快照恢复)不重跑初始化(像反序列化);
- 节点种类(数据节点/信号节点/仅输入节点/仅输出节点)是节点基类的派生形态,由声明决定(见 [节点类型](./graph-node-types.md));
- 门控(enable)inactive:整节点不执行 → 输出信号输出关闭并传导(§3)。
  门控是执行条件,不是端口信号:门控期间端口信号不变,到达的数据留在缓冲
  等待重开(节点暂停、数据不丢);端口信号关闭则是端口不存在 → 缓冲失效(§3.1)。

### 2.1 组缓冲与覆盖

- 每个有效输入端口有**一格缓冲**:新值覆盖旧值(重复值冲突是编辑责任);
- 组触发后该组输入缓冲清零,重新等待全套新值;
- 等待期间该组不执行,但输出信号保持 active(§3)——下游照常等待,不被拖住。

## 3. 端口信号:网络的控制面

**每个数据输入端口与每个数据输出端口都自带一个信号(电平),信号数量 = 数据端口数量。信号沿连线流动,像数据一样从上游流向下游——它决定哪些端口带电、数据走哪条路线。** 就像电路的通断,也像 if-else 的条件选择路径。

- **只有信号决定路线**:信号关闭的端口视为不存在,数据不走这条线;
- **信号逻辑必须显式**:信号的处理只发生在**信号节点**(AND/OR/NOT/比较器……)里;**数据节点永远不触碰信号处理逻辑**,只拥有一条引擎级的自动传导(§3.2);
- 信号节点可以接受数据(数据作为条件),让信号的逻辑在图中被显式表达。

### 3.1 输入端口:信号 + 缓冲

| 信号 | 端口状态 | 行为 |
|------|---------|------|
| active | 有效 | 参与触发与计算;缓冲空 = 等待,有值 = 已到达 |
| inactive | 关闭 | 视为不存在:不参与触发、不参与计算;缓冲失效 |

**缓冲失效时机**(实现锁定,见 §4):
- 电平变为 inactive 即失效:关闭期间投递的数据直接丢弃(不缓冲、不标新鲜);
- 关闭前已到达、尚未消费的旧值在节点访问时清除(幂等,不依赖组触发);
- 端口重新开启时缓冲必为空,等待新值——失效由关闭信号触发,与组是否触发无关。

输入信号的来源:
1. **显式信号线**:信号节点的控制输出连到端口的信号上——单个输入信号屏蔽;
2. **自动传播**:上游输出信号 inactive → 本输入信号自动 inactive;
3. 默认 active:不连线即带电。

**以信号线为准**:端口接入了显式信号线 → 信号电平以信号线为准(自动传导不生效);未接入 → 自动传导。

**扇入禁止**:每个输入端口至多一条数据线、至多一条信号线——多个来源的组合**必须显式使用信号节点**(如两个信号取 AND 输出),不允许隐式多源。

### 3.2 输出信号:数据节点唯一逻辑 + 信号节点

**数据节点**(不声明控制输出端口的节点)的信号行为只有一条规则,**实现永远不触碰信号**:

> 输出组的**对应输入组**(声明一一对应)的信号**全部关闭** → 该组输出信号输出**关闭**;组内至少一个输入信号 active → 输出信号保持 active。节点被门控(enable inactive)或熔断 → 全部输出信号输出关闭。

推论与边界:

- 关闭信号沿连线流向下游:下游对应输入信号随之关闭 → **下游不会等待一个永远不会到来的输出**——整段链自动"熄火",上游恢复后自动"复电",结构级门控不需要给每个节点拉控制线;
- **信号线电平变化显式唤醒目标**:控制输出变化 → 数据端口信号槽目标唤醒重推导——关闭传播不依赖数据投递的顺带唤醒(数据投递对关闭端口直接丢弃,不会再顺带唤醒),也不依赖下游恰好被其他事件访问;
- 等待输入中的节点:输入信号 active → 输出信号保持 active → 下游照常等待(规则自然给出,无需特判);
- 节点执行时未写某输出的数据 → 只影响是否投递值,不影响信号;
- 端口重新开启时缓冲为空(关闭期间的旧值丢弃),等待新值;
- 关闭的端口不读任何值:常量/全局读取绑定同样不读,参与计算的只有有效端口;
- 源节点(无输入组)的输出信号默认 active,仅门控/熔断可将其关闭;
- 数据节点的输出信号只有自动传导这一个来源,不可被外部接线覆盖;
- 子图边界:外部端口信号与内部映射端口信号一一传导(外部输入信号关闭 → 内部对应端口信号关闭;内部输出信号关闭 → 外部输出信号关闭);
- 关闭不作用于控制端口:控制网络永远活着(电平保持)。

**信号节点**(声明控制输出端口的节点)是信号逻辑的唯一所在地:

- 读输入信号、写输出信号——AND/OR/NOT/Latch、比较器、任何条件判断都是信号节点;
- **信号节点可以接受数据**(数据输入作为条件),让信号的逻辑在图中被显式表达;
- 信号节点的输出信号由实现显式写,未写保持原电平(不适用数据节点的自动传导);被门控时不执行,输出电平保持;
- 数据节点永远不写信号——信号的产生与处理全部经由信号节点,编辑器里一目了然。

## 4. 执行:脏节点传播(图路径遍历)

```
宿主注入输入事件(消息 / 外部完成 / 周期运行)
    → 注入目标按注入序入队,源节点按声明序播种(拉取型源节点尾播种)
    → 队列排空即静止:节点访问时满足触发条件即执行、产出即时投递、投递唤醒下游
    → 数据齐全即输出,不受声明顺序延误;无环部分结果与声明序无关
    → 每组每轮至多一次,反馈环跨轮迭代
```

**epoch 定义**:一次 `world.run(events)` 就是一个 epoch——一个逻辑因果传播域:
外部注入 → 播种 → worklist 传播 → 因果闭包 → 队列排空 → epoch 结束。反馈环在
同一 epoch 内被执行预算阻挡,下一 epoch 重新迭代;外部事件(宿主注入、异步结果)
开启下一 epoch。

**三个职责分开**:

- **Mark = 为什么访问这个节点**——结构化因果事实(kind/目标端口/来源节点/来源
  端口/槽):数据到达、电平变化、信号推导失效、播种……同一节点的多个 mark 合并、
  出队时一并消费,原因不丢;
- **NodeTurn = 本轮该节点已消耗的执行机会**(evaluation budget):源 step 一次、
  每组至多一次、输出信号重算至多两次、纯信号源再触发至多一次、熔断冷却扣减一次
  ——run() 重建本表 = epoch 边界;
- **节点状态 = 跨轮保存什么**——状态字段、缓冲、新鲜标记、熔断计数。

另有**因果 trace**(run + seq 确定性时间线):记录世界**为什么**变成这个状态,
独立于错误日志(程序打印了什么)、不进快照(世界是什么状态)。

- **因果序执行**:内部投递深度优先——一条传播路径走完再走兄弟分支(队列遍历,非调用栈递归);门控电平变化插队即时结算;信号关闭沿推导链惰性传播,已排队的数据触发不回头;
- **有界性来自 NodeTurn 预算**:队列排空即静止,不需要步数上限;
- **纯信号源**(Latch/AND/NOT/OR,无数据输入、无输入组)是电平函数:控制电平变化后同轮再触发一次——信号逻辑同轮收敛,不滞后;
- **全局写入按数据流因果序同轮可见**:拉取型源节点(无组、有数据输入的全局/常量读取者)尾播种——因果传播全部完成后执行,读到本轮最新写入;
- 环是合法设计(反馈环 = 跨运行迭代的状态机闭环):一个 epoch 内不递归展开,不挂起;
- 编辑器静态警告:无源环(没有源节点,永远不启动)。

## 5. 状态、确定性与异常

- 节点状态是**单写者**:执行时读取,产出新状态直接提交——无并发写、无事务冲突;
- 全局变量写 last-write-wins,顺序 = 数据流因果序(校验器对多写者告警);
- 随机性由**每节点独立随机流**提供(种子 = 世界种子 + 节点 id 派生):加节点、改声明序不扰动其他节点的随机轨迹;
- 节点异常:不产出任何输出 + 错误事件进日志;连续异常熔断、半开重试(策略沿用,"照发 None"改为"不发");
- **同一图、同一输入序列 → 同一结果**(因果序传播 + 独立随机流 = 确定可复现)。
- **同 tick 数据 + 关闭 → 单一结果**:同一节点同一次执行同时产出数据与关闭信号,
  下游在节点 turn 结束后才被访问,看到的必是最终状态(数据不触发、缓冲失效)。
  单线程队列 + turn 内固定代码序的结构保证,不是时序巧合;不同节点之间的先后
  由注入序 + 数据流因果序决定,同输入序列结果唯一。

## 6. 时间、节奏与外部世界

- **内核没有时间**:没有仿真时钟、没有时间戳、没有事件队列的排序问题;
- 世界 = 状态机/程序:**注入 → 传播至静止**。运行频率由宿主决定:实时 1 秒运行一次、消息到达才运行、编辑器预览连跑——节奏是宿主对"输入事件"的解释,不是内核机制;
- 外部系统(LLM 调用、HTTP)不属于内核:节点实现如何取得外部结果由宿主决定(同步阻塞,或挂起后注入完成事件),内核只认端口事件;
- 时钟/计时器等"时间节点"只是每轮运行执行一次的普通源节点——**时间只是世界可以接收的一类信号**。

## 7. 与旧模型(同步轮次)的关系

| 旧语义 | 新语义 |
|--------|--------|
| 每拍全图扫描,所有就绪节点都执行 | 注入后按数据流因果序传播,只有满足触发条件的节点执行 |
| 每轮必发契约(未写输出补 None) | 删除:不产出即不投递;信号决定端口是否带电 |
| None 是"新包" | 删除:None 只是节点主动发的一个值 |
| 就绪 = 一次性 warm-up | 每组触发 = 等本组全套新值(消费清零) |
| 同步/函数两种触发种类 | 输入组模型统一:单组 = 同步,单例组 = 函数 |
| 门控照发 None、不传播 | 门控 → 输出信号输出关闭,关闭沿信号传导 |
| mask 是节点上的特殊控制输入 | 信号内建在每一个数据端口上 |
| 数据包时间戳 / 轮次计数 | 无(事件即当下;日志用事件序号对齐) |
| 节点执行顺序无关 | 数据流因果序(传播即执行),确定性可复现 |

被否定的中间方案:

- ❌ **时间坐标 (t, δ, sequence) + 事件日历**:为"不同事件触发时间"建立的完整时间系统,复杂度不成比例。事件队列是实现的内部细节,不是世界模型;
- ❌ **拍事件作为内核机制**:节奏是宿主对输入的解释,内核不定义"拍";
- ❌ **全图重复扫描至静止**(曾作过渡实现:多遍扫描,收敛由触发驱动):每遍全图扫描、信号重算依赖"有触发才继续多遍"的隐式截断;脏节点传播只访问受影响的节点,队列排空即静止。

## 8. 被否定的方案(沿用)

- ❌ **令牌队列 join**(每个输入消费一个令牌、以最慢输入为节奏):引入队列堆积、丢弃策略、背压三个新问题;同步缓冲一格覆盖已经给出最简语义。
- ❌ **零延迟级联传播**(函数调用):反馈环导致无限递归;脏节点传播(队列遍历,非调用栈递归)+ 每组每轮至多一次解决。
- ❌ **共享黑板**:数据写入的消费时机不确定;数据随信号流动则路由与消费时机由连线结构确定。
- ❌ **运行时类型强制**:类型注解只做编辑期静态检查,运行时鸭子类型(见 [节点类型](./graph-node-types.md) §5)。
