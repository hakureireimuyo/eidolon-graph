# 节点协议:Graph Kernel ↔ Node 扩展边界

> 本文档定义 Eidolon 最核心的稳定 ABI —— **Graph Kernel 与 Node 之间的协议**。
> 它是语言无关的 canonical 规范(Python 参考实现见
> `eidolon_graph/engine/protocol.py`),并被 `tests/test_node_protocol_abi.py`
> 的协议级测试锁定:任何改动破坏本协议 = 破坏所有节点包。
>
> 相关文档:[执行模型](./graph-execution-model.md) · [节点类型](./graph-node-types.md) ·
> [持久化与编辑](./graph-persistence-and-editing.md)

## 1. 核心命题:内核不知道领域

```
Graph Kernel = 图模型 + 执行模型 + 节点协议 + 端口/连线语义 + 状态/快照 + 调度 + 内置原语
Node Package = 节点声明 + 节点状态 + 执行逻辑 + 节点资源 + 节点配置
```

内核只关心:`Node A,输入 prompt,输出 response,状态若干,execute(...)`。
`execute()` 内部是 OpenAI / DeepSeek / 本地模型 / 多模型路由 / Agent Loop ——
**全部是节点自己的问题**。LLM、Context、Agent、Tool、Resource 都不是
Graph Runtime 的特殊概念,它们只是图中的某种节点。

稳定边界一经冻结,一个节点只需:实现本协议 → 注册自己的 Node Type →
内核即可执行它。节点有两种居住形态(注册方式完全相同):
- **内核封装层**(如 `eidolon_graph/nodes/llm`):内核引用独立能力子项目
  (如 eidolon-llm,零图概念),把能力包装成节点;
- **独立节点包**(外部项目):实现协议并注册(宿主显式登记)。

仓库拆分因此从"工程管理独立"升级为"架构语义独立"。

## 2. 节点类型声明(协议第 1-4 问)

**节点类型 = 声明式资产**,像类一样只定义接口;实例 = 类型 + 配置覆盖 + 连线。

| 声明 | 含义 |
|------|------|
| `name` | 类型名(注册与图资产引用的键) |
| `data_in` / `data_out` | 数据端口:可选参数、const 绑定、全局读写 |
| `control_in` / `control_out` | 控制端口(信号):门控 / 电平语义 |
| `state` | 状态字段表(保序、默认值)——**实例跨轮事实的唯一存储** |
| `config` | 配置字段表(类型默认 + 编辑期覆盖) |
| `groups` | 输入组 = 函数调用:组内全部有效输入有新值即执行、消费清零 |
| `init_in` | 初始化输入:`__init__` 参数端口(构造时一次性) |
| `auto` | 自走源:每轮运行自动执行一次(时钟 / 脉冲等) |
| `impl` | 实现绑定(kind=code / subgraph,name = 注册键) |

- 声明 = 规则,实现 = 代码,二者分离(规则与事实分离原则的节点版);
- 声明的序列化形态 = 节点类型资产(JSON),编辑器调色板 / 校验器 / 快照兼容
  全部由它驱动,前端不硬编码任何节点清单。

## 3. 执行协议(第 5-7 问)

**内核调度 = worklist 脏传播**(图路径遍历,非全图扫描):注入目标按注入序
入队、源节点按声明序播种;节点访问时满足触发条件即执行、产出即时投递、
投递即唤醒下游;队列排空即静止。一次 `run(events)` 是一个 epoch(逻辑因果
传播域):注入 → 播种 → 传播至因果闭包 → 静止;反馈环被本 epoch 的执行预算
(每组至多一次、源 step 一次、信号重算至多两次)阻挡,下一 epoch 重新迭代。

实现侧接口(Python 参考实现):

- `tick(ctx) -> TickOutput`:一个输入组执行一次。`ctx.group` = 组名(源节点
  自走执行为 `"step"`);`ctx.data_in` 只含本组已解析输入(被信号关闭的端口
  不出现);`ctx.control_in` 电平永远有定义;`ctx.state` 为当前状态深拷贝;
  `ctx.config` 只读;`ctx.rng` 本节点独立随机流(种子 = 世界种子 + 节点 id
  派生,同图同输入序列结果唯一)。
- `TickOutput.data_out`:数据产出(不写即不投递);
- `TickOutput.control_out`:信号产出(**仅信号节点可写**,未写保持原电平);
- `TickOutput.state`:状态变更字段增量(与现有状态合并)。
- `init(ctx) -> state 增量`:初始化输入就绪后执行一次,方法组在此前不执行。
- `schedule(ctx) -> 秒数`:实时模式下源节点的发射周期(每轮发射后按最新
  状态重查;`None` = 每轮发射)。

## 4. 异步协议(第 8-9 问)——**宿主完成注入**

> **内核没有"异步"概念。** 节点不产出即等待;外部结果到达后由**宿主**
> 注入完成事件,与用户点击 Input 注入完全同构。内核文档的核心命题已写明:
> "事件驱动不在乎事件从哪来——LLM 响应、HTTP 返回、定时器、用户点击,
> 都是同一类东西。"

生命周期(以 LLM 节点为例):

```text
1. 组 "call" 触发(prompt 齐全)→ tick 发起外部调用,把 pending 凭证
   (调用 id / 会话 token)写入 state,不产出任何输出 —— 节点进入等待;
2. 内核继续推进:等待节点不产出即不唤醒下游,其他节点照常传播,源节点
   照常发射 —— "不同节点不同步推进"是普通节点的天然语义,不是 LLM 特例;
3. 外部结果到达(节点包自带的适配层收到响应)→ 宿主调用
   world.run([Event(node, "_result", 结果)]) 注入完成事件;
4. 完成事件 = 新 epoch 注入 → 组 "complete"(inputs=[_result])触发 →
   tick 产出 response → 沿数据流因果传播下游;
5. 因果 trace(run + seq 确定性时间线)记录两个 epoch 的全部因果:注入、
   触发、投递 —— 确定性可复现依旧成立。
```

约定:

- **等待 = 不产出**。内核不维护 pending 队列,不知道也不关心外部工作;
- 完成端口(如 `_result`)是**可选参数端口**(optional):不接线不阻塞触发,
  注入事件到达即新鲜;
- **空触发必须容忍**:可选/绑定端口不计入触发条件,组内触发端口集合为
  空时组在每次节点访问都被"空触发"(触发条件真空为真——这是 Random
  "只连 seed 也产生事件"语义的推论)。实现必须守卫:空触发时静默等待,
  不产出、不改状态(完成组收到空触发 = 结果未到,保持 pending);
- **pending 凭证必须存进 state 字段** —— 快照/读档续跑天然覆盖
  (见 §5),恢复后宿主适配层按凭证继续等待或按丢弃处理(节点包业务);
- 超时 / 重试 / 取消 / 多路复用:**全部是节点包自己的业务**,内核不介入。

被否定的方案:内核原生挂起(`TickOutput.defer` + `world.complete()`)——
需要内核新增"等待中"执行状态、快照覆盖 pending、重定义 epoch 语义、
trace 处理非注入唤醒,对"注入→传播→静止"的同步原子模型是实质性侵蚀,
而收益(统一超时/取消)全部可在节点包层获得。

## 5. 持久化协议(第 10 问)

- **state 字段表是节点跨轮事实的唯一存储**:实例其余属性一律不跨轮;
- 快照 `NodeSnapshot` 覆盖:state / 输入缓冲 / 新鲜标记 / 信号电平 / 熔断器
  / 内嵌子图(递归)。异步 pending 凭证在 state 中(§4),快照即完整世界事实;
- 快照兼容:图资产 `kernel_version` 主版本一致 + 节点类型名全部存在,
  否则拒绝读档;
- 换实现(如 LLM 节点换引擎):宿主提供迁移函数
  `(旧状态 dict, 新 NodeType) → 新状态 dict`,由编辑事务驱动。

## 6. 注册与发现(第 11、13 问)

- **宿主显式注册**:`registry.register(type_name, impl_cls)`。节点包是普通
  库(零依赖内核的鸭子类型测试桩模式由 eidolon-character /
  eidolon-graph-project 验证),宿主 import 节点包并登记;
- 不引入入口点自动发现:注册时机由宿主决定(编辑器 = `builtin_env`,
  运行时 = 各自组装),内核保持零发现机制、零隐藏依赖;
- 重名注册报错;类型资产与实现绑定经 `impl.name` 关联。

## 7. 版本与迁移(第 12、14 问)

| 层次 | 版本机制 |
|------|----------|
| 内核格式 | 图资产 `kernel_version`(主版本兼容校验) |
| 节点类型 | 类型名 + 节点包 schema 版本(节点包自管,与图工程条目级版本同构) |
| 状态迁移 | 换实现迁移函数(§5);状态字段默认值 = 旧快照缺字段的兜底 |
| 快照兼容 | kernel_version 主版本 + 类型名存在性;元数据类条目损坏可重建 |

## 8. ABI 稳定性承诺

**稳定**(改动 = 破坏所有节点包,须随协议版本演进):

- 声明模型与序列化形态(§2)、组触发语义、TickContext/TickOutput 契约(§3)、
  异步约定(§4)、快照字段(§5)、注册接口(§6);

**内部实现**(可自由重构):worklist 数据结构、播种顺序、信号重算上限等
——它们由执行模型文档约束语义、由协议测试锁定可观察行为。
