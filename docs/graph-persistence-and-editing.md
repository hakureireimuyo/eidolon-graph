# 持久化与编辑

> 本文档定义**数据分类、快照结构与编辑事务**。原则:规则与事实分离——图(规则)是资产,节点状态(世界事实)是快照,分开存储;改图不动事实。
> 相关文档:[图运行时总纲](./graph-runtime-overview.md) · [执行模型](./graph-execution-model.md) · [资产系统](./graph-assets.md) · 人格、意图与认知链(eidolon-runtime 仓库 docs/graph-cognitive-chain.md)

## 1. 核心命题

> **世界是确定性可复现的:存档 = 规则资产引用 + 世界事实快照 + 执行器状态;编辑 = 停止世界的事务,校验后原子提交。**

## 2. 数据分类

| 类别 | 归属 | 何时变 | 持久化 |
|------|------|--------|--------|
| 图拓扑 | 图资产 | 仅编辑期 | 是(资产,版本化) |
| 节点配置(只读字段) | 图资产 | 仅编辑期 | 是(资产) |
| 节点状态(可写字段) | 世界事实 | 每次执行时 | 是(世界快照) |
| 端口状态(缓存值 + pending + 资格电平) | 执行器状态 | 每次执行后 | 是(随快照) |
| 全局变量 | 世界事实 | 运行时 | 是(世界快照) |
| 事件日志 | 历史 | 只追加 | 可选(可截断) |
| KV cache 等运行时产物 | 优化结构 | 每次运行生灭 | 永不 |

## 3. 快照结构

**两次事件注入之间世界静止**,是天然 checkpoint 点——级联结束拍快照,世界状态确定且自洽:

```
快照 = 图资产版本引用
     + 节点状态表
     + 端口状态表(缓存值 + pending + 资格电平/资格 pending;触发前的半满状态)
     + 全局变量表
     + 运行序号(run_no)+ 事件日志(可截断)
     + RNG 状态(每节点独立流)
```

### 3.1 为什么端口状态必须持久化

不能只存节点状态、读档后重新等待:输入组触发前的 pending 半满状态必须原样恢复(慢速源等一小时,缓存里就得留着半套旧值)。快照包含端口状态(缓存值 / pending / 资格电平),读档 = **完整恢复运行中状态**,世界从断点精确续跑。

### 3.2 为什么 RNG 必须持久化

既有文档原则"规则决定可能空间,随机性决定具体轨迹"——轨迹要可复现,存档就必须含 RNG 状态;否则读档后世界走一条不同的随机轨迹,与"确定性随机"矛盾。

同一逻辑下,**资产版本也是轨迹的变量**:`World + Rules + State + RNG + 资产版本 → Trajectory`。同一世界、同一 RNG、只替换人格资产版本,轨迹差异可归因于资产本身(见 人格、意图与认知链(eidolon-runtime 仓库 docs/graph-cognitive-chain.md) §7);旧存档继续引用旧资产版本,新世界升级新版本,二者互不污染。

### 3.3 日志是可截断的历史

对齐既有文档的 Event Sourcing:存档 = 状态全量 + 日志可截断。日志供调试/回放用,不是世界事实的载体;历史 = 日志,状态 = 数据库。

## 4. 编辑模型

### 4.1 任何人可编辑

编辑者是任何人:开发者或用户。编辑器(可视化编排页面)是产品的核心界面;节点类型资产与图资产两层都可以编辑——用户按自己的意图设计、编辑、分发规则。

### 4.2 编辑事务

**编辑时冻结事件注入**——不冻结可能出现意料之外的事情,产生大量输入污染传递的数据。事务流程:

```
进入编辑态:世界冻结;事件注入暂停;用户消息等输入源排队
     ↓
校验(见 §5 清单)
     ↓
提交:状态迁移一次完成(原子)
     ↓
恢复事件注入
```

没有"边改边迁"的中间态。编辑事务与存档/读档构成两个确定性边界。

### 4.3 编辑动作与状态迁移

| 编辑动作 | 状态迁移 |
|---------|---------|
| 改参数/字段值(连线不变) | 全部保留,即时生效 |
| 改连线 | 节点状态保留;被断开的端口失去值来源,输入缓冲重置、关闭状态重算 |
| 增节点 | 初始化输入执行一次(__init__),方法组从等待开始 |
| 删节点 | 其状态销毁或归档(可询问用户) |
| 换实现(同协议) | 状态保留;协议不兼容则迁移函数或重置(重置后重新初始化) |

原则:**规则与事实分离**——改图不动状态,除非显式删节点。

## 5. 校验器清单

提交前依次执行:

1. 端口绑定合法性(裸数据端口报错);
2. 连线 kind 匹配:data→data、control→control,交叉连线报错;
3. 引用存在性(未声明的全局变量/常量 → 抛异常);
4. 连线类型兼容(双方均声明类型时,仅数据通道);
5. 同一节点多输出写同一全局 → 报错;
6. 全局变量声明带默认值;
7. 静态提示(非错误):无源环、无门控环、多写者。

## 6. 待定(最小验证时决定)

- 编辑粒度细节:改图时运行中状态的增量适配策略;
- 热编辑(运行中编辑)是否成为未来版本能力;
- 存档格式:人类可读(DSL/YAML)优先,二进制后置;
- 子图端口映射的编辑细节。
