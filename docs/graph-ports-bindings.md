# 端口、绑定与输入资格

> 本文档定义节点端口的语义模型:**事件是唯一传播事实;端口声明接受哪种事件;
> 连接状态决定输入语义(静态/动态);信号是输入资格(qualification),不是
> 输出状态报告。**
> 本文档按 2026-08-19 端口语义抽象收敛模型重写(决策记录见
> [端口语义抽象收敛](./graph-port-capability-composition.md))。

> [节点类型](./graph-node-types.md) · [触发语义](./graph-trigger-semantics.md) ·

## 1. 核心命题

> **连线 = 动态接口(推,外部事件驱动);内嵌绑定 = 静态接口(拉,节点自身
> 拥有的默认属性);信号 = 输入资格(决定已到达的数据何时具备参与执行的
> 资格);三种机制不互相污染。输出侧不存在隐式信号。**

## 2. 端口语义与绑定模型

### 2.1 端口声明

| 端口 | 语义 |
|------|------|
| `DataIn` | 数据输入:一格缓存(Replace 默认 / Append 声明)+ pending;可声明**资格槽**(Signal 绑定,可选) |
| `DataOut` | 数据输出:执行产出即投递(Data Event) |
| `TriggerIn` | **函数调用入口(激活请求)**:Data Event 到达 = 载荷 + 激活;Signal Event 到达 = 激活(每次 Signal Event 都是新的请求);无绑定/默认 |
| `SignalIn` | 信号输入(取代旧 control-in):`enable`(节点级资格)或端口级资格;level + pending |
| `SignalOut` | 信号输出(取代旧 control-out):**仅信号节点声明**;电平输出 = Signal Event |

- **DataIn 的资格槽是声明级、可选的**:声明了资格槽的数据端口 = 旧模型的
  "数据 + 信号"完整端口(如 Join 的 a/b);未声明 = 纯数据端口(Random 的
  num/seed/range)。编辑器渲染内核声明的组合,不做"隐藏/暴露"决定;
- 端口语义的三维正交组合(声明 × 绑定模式 × 缓存策略):

  ```text
  Port Semantic(Data / Signal / Trigger)
      ×
  Binding Mode(Static / Dynamic,由连接状态决定)
      ×
  Cache Policy(Data 端口:Replace / Append)
  ```

### 2.2 静态 / 动态接口(输入侧)

**连接状态决定输入语义,而不只是输入来源。**

| 状态 | 语义 | 来源 |
|------|------|------|
| **静态**(未连接) | 节点自身拥有的输入:默认属性 / 配置值 / 常量绑定;条件恒满足,不等待事件 | 默认值、常量、全局读取绑定(声明) |
| **动态**(已连接) | 外部事件驱动的输入:必须等待实际事件到达;初始状态 = "尚未收到事件" | 连线 |

- 未连接 Signal(资格槽):**条件恒成立**——这是结构属性,不是隐式初始事件
  (已连接后必须等实际 Signal Event,不存在默认事件);
- 未连接 Data:使用默认属性;连接后由事件驱动;
- 静态与动态是**同一端口的两种运行模式**,不是两种端口类型;
- 可选参数:未接线 = 静态(回退配置默认值,校验豁免);接线 = 动态(参与
  触发等待);
- 常量/全局读取绑定 = 静态输入:不参与触发、不消费,值随读随用;
- **连接动作 = 语义转换**:`connect(port)` 把端口从静态转换为动态,
  readiness 规则随之改变,由内核吸收进 Port Readiness 计算,节点实现
  不需要写 `if connected:`。

### 2.3 端口状态与资格

**Event 是事实,State 是事实的当前结果,pending 是状态变化是否尚未被当前
执行消费的标记。**

```text
Data Port
├── value         缓存值(Replace 覆盖 / Append 累积)
└── pending       是否有尚未消费的 Data Event

Signal Port
├── level         当前电平(HIGH / LOW;消费后保持)
└── pending       是否有尚未消费的 Signal Event(资格)

Trigger Port
└── pending       是否有尚未消费的激活请求
```

- **Signal 的 level 与 occurrence 独立**:`S1 → S1`(同电平连续两次)是两次
  独立的 Signal Event、两次资格,不能用电平变化判断"是否更新";
- 执行消费 pending,value/level 保持;
- **低电平(LOW)语义**:

  ```text
  Signal = LOW:
      Data Event 照常进入、照常缓存(cached = D4 保留)
      effective_value = 默认属性(参与计算时表现为默认值)
  Signal = HIGH:
      effective_value = cached
  ```

  禁用的是**参与执行的资格**,不是接收能力;"清空缓存/拒绝数据"都是错误
  实现;
- 缓存策略是端口属性:普通节点 = Replace;Buffer 类 = Append。高频生产者
  连接低频消费者时旧值被覆盖,是 Replace 的正常结果(需要逐个消费时
  显式插入 Buffer 节点)。

### 2.4 输入组与触发策略

**输入组 = 函数**;组的触发 = **Readiness 检查**:

```text
Event → Port State 更新 → 节点 Dirty → 调度 → 检查 Readiness → Ready 则执行
```

- **Dirty ≠ Execute**:任何相关输入状态变化(Data 或 Signal)都使节点
  Dirty、重新评估 Readiness;Data 与 Signal 在调度层面完全对称,都不拥有
  "触发权";
- 组策略(`InputGroup.policy`)描述 **pending 如何聚合为 Readiness**,不描述
  执行逻辑:

  | 策略 | Readiness 条件 | 适用 |
  |------|---------------|------|
  | `ON_ALL_DATA_READY`(默认) | 组内全部动态 Data 端口 pending | 组合节点(Join 类) |
  | `ON_ANY_DATA` | 任一动态 Data 端口 pending | 任一到达即处理 |
  | `ON_TRIGGER` | 任一 TriggerIn pending | 纯事件节点(Buffer.flush) |
  | `ON_DATA_AND_TRIGGER` | 数据齐 pending + Trigger pending | 显式门控执行(Timer.arm) |

- **资格条件叠加在 pending 之上**:已连接资格槽的端口,其 Readiness 为
  `pending AND level == HIGH`;未连接资格槽 = 条件恒成立;
- 执行后消费本轮 pending,重新等待;
- **Activation 与 Readiness 分离**:基类默认隐式激活(状态变化 → 自动检查
  Readiness);声明显式 TriggerIn 改变激活策略(Buffer:Trigger 到达才请求
  输出,数据到达只 Append)。普通节点可以没有显式 Trigger;
- 静态输入(绑定)不参与触发、不消费。

### 2.5 输出:Output Emission,无隐式信号

- 一次 NodeTurn 的输出 = **Output Emission**:普通数据节点只产 Data Event;
  **Signal Event 仅当节点显式声明 SignalOut(信号节点)时存在**;
- **不存在"无输出 → 输出信号 LOW"的自动传导**:没有 Event 就是没有事实
  发生;不产生"无事件事件";
- 节点因拓扑原因永远无法产生输出 → 下游等待 → **拓扑诊断给出警告**
  (上游无输入、不能自行产生事件,下游又在等待该输入 = 潜在死锁拓扑),
  不是内核机制;
- 需要控制流时显式构造:数据 → 数据转信号节点(DataToSignal /
  CompareToSignal / ThresholdToSignal / PredicateToSignal / Script → Signal)
  → Signal → 受控输入。控制逻辑从内核提升到图本身;
- **数据节点** = 不声明 SignalOut 的节点;实现永不触碰信号。**信号节点** =
  声明 SignalOut 的节点,是信号逻辑的唯一所在地(读输入信号、写输出信号,
  未写保持原电平),可以接受数据作为条件。

### 2.6 输出端口的绑定

| 输出端口 | 绑定 | 语义 |
|---------|------|------|
| 数据输出 | 连线 | 执行时产出即投递(Data Event),推给下游 |
| 数据输出 | 全局写入 | 执行时写入命名的全局变量(状态,非输出源,见 §3) |
| 信号输出 | 连线 | 信号节点显式产生(Signal Event) |

### 2.7 瞬态与持久

- 动态(连线)输入 = **瞬态**:事件到达产生 pending,执行消费;
- 静态(绑定)输入 = **持久**:不参与触发、不消费,值随读随用;
- "配置一直有效"用绑定,不需要消费策略类新机制——绑定种类已经区分了
  两类输入。

## 3. 为什么全局变量不是输出源

全局变量是**状态**,不是输出。它被读取时不产生输出、不唤醒下游:

- 全局被改 → 没有任何节点被触发;
- 读取它的节点在**下一次因其他原因执行时**才看到新值;
- 读取是拉,不是推——全局写入不进入传播,不会产生输入污染。

## 4. 输入资格:信号如何控制数据参与

### 4.1 资格矩阵

Data Port 的两个正交维度:

```text
维度一:数据来源    Static / Dynamic
维度二:控制绑定    Uncontrolled / Signal-Controlled
```

| Data Port | 资格绑定 | 数据来源 | 当前有效性 |
|---|---|---|---|
| 无连接 | 无 | 默认属性 | 始终有效 |
| 有数据连接 | 无 | 动态事件 | 始终有效 |
| 无数据连接 | 有 Signal 连接 | 默认属性 | 由 Signal 控制 |
| 有数据连接 | 有 Signal 连接 | 动态事件 | 动态数据持续接收,有效性受 Signal 控制 |

- **Signal 关闭的是"端口 → 节点执行"的资格,不是"来源 → 端口"的接收**;
- 四种情况是两维组合,不是四种端口类型;
- 节点级资格(enable):同一机制,作用域为整节点——`enable.level == LOW`
  → 节点不执行;数据照常接收缓存(节点暂停、数据不丢);`HIGH` 后重新
  readiness 检查。**enable 与端口资格不是两种机制,是同一机制的两种作用域**
  (节点级 / 端口级)。

### 4.2 资格条件(Readiness 中的叠加)

```text
端口已连接资格槽:
    pending(Signal Event 到达且未被消费)
    AND level == HIGH
    → 该数据端口具备资格

端口未连接资格槽:
    条件恒成立(结构属性)
```

- 未连接资格槽时,普通动态数据端口的 Readiness = `pending` 即可——这正是
  "普通参数节点数据到达即参与"的自然行为;
- 连接资格槽后,必须 Data.pending AND Signal.pending AND Signal.level==HIGH
  共同成立才执行——这消除了数据/信号到达顺序对结果的影响
  (见 [端口语义抽象收敛](./graph-port-capability-composition.md) §4 案例)。

### 4.3 扇入禁止

每个输入端口至多一条数据线;资格槽至多一条信号线——多个来源的组合
**必须显式使用信号节点**(如两个信号取 AND 输出),不允许隐式多源。

### 4.4 连线校验

| 连接 | 合法性 | 语义 |
|------|--------|------|
| Data → Data | ✓ | 参数绑定(数据传递) |
| SignalOut → SignalIn / 资格槽 | ✓ | 控制绑定(资格) |
| Data → TriggerIn | ✓ | 激活请求(载荷 + 激活) |
| Signal → TriggerIn | ✓ | 激活请求(每次 Signal Event 一次) |
| Signal → 纯数据端口 | ✗ | 资格槽未声明,类型不匹配 |
| Data → SignalIn | ✗ | 类型不匹配 |

### 4.5 缺氧式离散信号网络

端口信号网络的灵感(离散信号网络——机器自己知道何时输出信号,接收端只
需要知道"收到信号后做什么")在资格模型下依然成立,且更纯粹:

- **信号节点**(AND / OR / NOT / Latch / 比较器 / 开关 / 计时器 / 数据转
  信号节点)显式产生 Signal Event;
- **受控输入端口**接收 Signal Event → 更新 level + pending → 参与资格;
- 用户编辑的不是"程序",而是在搭建一个可运行的世界自动化网络——控制
  逻辑全部显式存在于图中;

例:温度超过 30℃ 且玩家进入房间时启动空调:

```
[世界温度] → [温度比较器] ──信号──┐
                                  ↓
[玩家位置] → [房间判断器] ──信号── [AND] ──信号──→ [空调].enable
```

用户同样可以自制 `[剧情条件判断器]` `[任务完成判断器]`——对运行时没有
区别。

### 4.6 结构级门控(资格模型下的表述)

结构级门控 = **入口处一个 enable 资格信号,整段子系统失去执行资格**:

```
剧情状态 → [条件节点] ──信号──→ [战斗系统].enable
                                   │
                                   ├→ [战斗状态] → [敌人 AI] → [行为规划]
                                   └→ [LLM] → [动作生成] → [世界状态更新]
```

- `enable.level = LOW`:整段子系统内的节点不执行(内部状态不更新,LLM 节点
  不进入 prompt 构建、不产生 token——成本门控保持);
- 节点数据照常接收缓存(不丢),资格恢复后继续;
- **不再有"输出信号自动传导熄火"**——被门控的节点不产出任何事件,下游
  的等待由拓扑诊断负责提示(上游存在可恢复的输入来源时属正常暂停;上游
  结构性无法产生事件时给出警告);
- 章节门控(多个系统同时存在于图中,只有被授权的计算网络执行)依然成立:
  各系统入口的 enable 资格由剧情信号驱动。

### 4.7 数据网络与信号网络的对偶

图中存在两种流,在节点内部交汇:

```
                数据网络:  世界状态 ─────→ 节点 ─────→ 世界状态
                信号网络:  资格    ─────→ 节点 ─────→ 资格

        data ────────────────→│            │───→ data
                              │    NODE    │
        signal ──────────────→│            │───→ signal(仅信号节点)
```

- **数据流回答**:"世界中有什么、发生了什么、状态是什么。"
- **信号流回答**:"哪些输入现在具备参与执行的资格。"
- 数据→信号(比较器 / DataToSignal)、信号→数据(受控输入)的转换必须经
  节点内部,端口层不混。

### 4.8 反模式:数据伪装成控制

不用资格、改在数据里塞 `{enabled: false, payload: ...}`,会让每个节点都
出现 `if not input.enabled: return`——控制逻辑重新隐藏进节点内部,与
"一切显式"原则冲突。有了声明式资格槽与信号节点,图的视觉结构本身就
表达"数据从哪里来,以及这段网络的哪些输入何时有资格参与"。

**世界语义与计算语义的边界**:

- `data: world.reality = MEAT`(世界现在是不是血肉世界)→ 数据,可以被
  任何节点读取;
- `signal: meat_chain = active`(血肉世界相关计算的执行资格)→ 信号,只
  决定输入资格;

两者即使最终都表现为 `true / false`,也不能因此合并。

## 5. 可编排的控制模式

- 旁路某段数据处理:资格槽 LOW(数据照常缓存,不参与执行);
- 暂停一条链:链入口 enable 资格 LOW(整链暂停,数据不丢);
- 给反馈环调速:信号节点产生方波 Signal Event(每次事件都是新的资格,
  同电平重复也有效);
- 章节门控:按剧情状态启用/关闭整段子系统——多个系统同时存在于图中,
  只有被授权的计算网络被执行(实例见 应用模式与场景图式(eidolon-runtime
  仓库 docs/graph-application-patterns.md) §6 双世界)。

全部是连线与声明,不是新原语。

## 6. 校验相关

- 端口绑定合法性:裸数据端口报错;绑定必须指向已声明资产;
- 连线 kind 匹配:data→data、signal→signal(或资格槽)、交叉连线报错;
  Signal → 纯数据端口(未声明资格槽)报错;
- 扇入禁止:每输入端口至多一条数据线、资格槽至多一条信号线;
- 引用存在性:绑定引用的全局变量/常量必须已声明;
- 完整校验清单见 [持久化与编辑](./graph-persistence-and-editing.md) §5;
- 死锁拓扑警告(静态提示,非错误):上游结构性无法产生事件、下游又在等待
  该输入。
